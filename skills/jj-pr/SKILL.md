# jj-pr

In jj repos, use `jj-pr` to turn commits into GitHub PRs. It handles the whole flow: bookmark creation, pushing, PR creation, pointing each PR in a stack at the one below it, and maintaining a "PR Stack" section in each PR body. Do not hand-roll this with `jj git push` and `gh pr create`.

## Usage

```sh
jj-pr                     # PR for the nearest pushable change to @
jj-pr <revset>            # PR(s) for a revset; a range creates one PR per change
jj-pr 'trunk()..@'        # a PR for every change from trunk to the current change
jj-pr --dry-run <revset>  # preview what would happen without pushing anything
jj-pr --help 							# show all options
```

What it does: finds the nearest pushable change to the revset (skipping unpushable ones, e.g. empty or missing a description), creates a bookmark there if none exists, pushes, creates any missing PRs, re-points stacked PRs at each other, and updates PR descriptions with stack links. Running it on a change in the middle of an existing stack inserts a new PR there and re-points its neighbors.

## Notes for agents

- Changes must have descriptions to be pushed to GitHub. When you create new changes, make sure you `jj describe -m <message> -r <revision>` them before executing `jj-pr`.
- `jj-pr` creates bookmarks at changes automatically, by combining the user's `jj-pr.bookmark-prefix` from their jj config along with an autogenerated unique bookmark name based on the commit message. 
- Do not create bookmarks manually unless instructed. This preserves the user's preferred automatic bookmark naming scheme.
- Run `jj-pr --dry-run <revset>` first and check the plan before pushing anything.
- Follow with `jj-pr --yes <revset>` to push. *Never* use `jj-pr --yes` without first running `jj-pr --dry-run` to verify the plan. Even for trivial changes, always run `--dry-run` first. This is to prevent accidentally pushing changes if the user made simultaneous modifications to the repository.
- You must call `jj-pr` with one of `--yes` or `--dry-run`. Otherwise, the CLI will enter its interactive mode and hang waiting for user input.
- `jj-pr`'s setup guide recommends adding an alias to jj to execute it. The user may invoke or refer to `jj pr` commands which should be treated as equivalent to `jj-pr` invocations. Always prefer `jj-pr` over `jj pr`.

## Creating One PR

- To create a PR for a single change, run `jj-pr <revset>` where `<revset>` is the jj changeId of the change you want to push.

prefer explicitly passing a `<revset>` to `jj-pr` over relying on the default behavior of pushing the current change, as it avoids accidentally pushing unintended changes.

## Creating Multiple PRs at once

- To create multiple PRs at once, run `jj-pr <revset>` where `<revset>` is a jj revset expression specifying the changes you want to push.

Example:
```sh
jj-pr muxvv lkum tvuu # creates three PRs
```


## Updating Multiple PRs

- `jj-pr <revset>` will automatically push all bookmarks that are related to `<revset>`. To push a stack of many PRs after making changes, such as fixups, you only need to specify one bookmark name or change in `<revset>`. Avoid overspecifying many changes in `<revset>` just to push a stack of PRs.
